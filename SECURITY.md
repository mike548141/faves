# Security policy

## Reporting a vulnerability

Please report privately through this repository's
[GitHub security advisories](https://github.com/mike548141/faves/security/advisories/new)
— **not** a public issue, and not by email.

This is a personal project maintained in spare time. Expect an
acknowledgement within about a week. There is no bounty.

## What is in scope

The site is a static, offline-first PWA. It has **no backend, no
accounts, no login and no third-party code in `site/`** — no framework,
no CDN, no trackers. (Cloudflare, the host, injects its own cookie-free
Web Analytics beacon at the edge; see *Privacy*.) That removes most of the usual attack surface,
and it also means the interesting reports are the few things that are
left:

- **The service worker** (`site/sw.js`) — cache poisoning, a stale or
  wrong-origin response being served, or a versioning fault that pins
  visitors to old data.
- **The share codec** (`site/js/share-codec.js`) — group orders and
  shortlists travel in a URL fragment. Anything that lets a crafted link
  inject content, escape the parse, or corrupt stored state.
- **Stored preference handling** — favourites, ratings, profiles and
  settings live in the browser on the visitor's own device. Anything that
  lets one origin, page or profile read or overwrite another's.
- **Cross-device sync**, once shipped — the payload is end-to-end
  encrypted and carried by a bearer sync-code. Weaknesses in the
  encryption, the code's entropy, or the server's ability to read
  plaintext are all in scope.
- **Content injection** — menu data is JSON rendered into the DOM. Any
  path where data becomes markup or script.
- **Outbound links** — maps handoffs build URLs from venue data.

## What is not in scope

- **The absence of a backend, accounts or authentication.** Deliberate.
- **Data accuracy.** A wrong price or stale opening hours is a content
  bug — please open a normal issue.
- **Anything requiring physical access to an unlocked device.** All
  preference data is deliberately device-local and unencrypted at rest;
  that is a documented trade-off, not a defect.
- **Missing rate limiting, CSRF tokens, or session handling.** There are
  no sessions and no server to defend.
- Reports generated by a scanner with no demonstrated impact.

## Privacy

The site has no accounts and collects no personal information.
Favourites, ratings, order tallies and settings stay in the browser's
own storage on the device, and a device's location never leaves it.
There are no cookies.

What *is* recorded is that the site is used (owner-ruled 2026-09-28,
[ADR 0134](docs/decisions/0134-anonymous-visit-analytics-are-allowed-and-disclosed.md)):
Cloudflare, the host, keeps its standard edge request logs (which, as
for any website, include the requesting IP address and browser) and
injects its cookie-free Web Analytics beacon, which reports page loads
in aggregate. Both serve usage, security and cost management. The
optional cross-device sync stores only an encrypted blob and logs
nothing (`worker/README.md`).
